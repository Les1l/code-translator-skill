# 跨语言讲解手册

配合 `SKILL.md` 使用。SKILL.md 定流程与纪律，本文件提供"具体怎么讲"的对照材料。在判定语言、需要通用讲法、或怀疑自己在拿另一门语言的概念硬套时读本文件。

## 1. 先判定语言与范式

在鸟瞰那一步就要写明：**什么语言 + 什么范式 + 这段代码属于哪一类**（脚本 / 函数 / 类 / 模块 / 配置 / 查询 / 样式）。

范式决定讲解重点：

| 范式 | 典型语言 | 讲解重点 |
|---|---|---|
| 命令式 / 过程式 | C、Go、Shell、Python 脚本 | 执行顺序、状态如何被逐步修改 |
| 面向对象 | Java、C#、Ruby、Python 类 | 对象生命周期、封装边界、多态派发点 |
| 函数式 | Haskell、Elixir、F#、Rust 迭代器链 | 不可变性、纯函数、组合与惰性求值 |
| 声明式 | SQL、HTML/CSS、Terraform、K8s YAML | 描述目标状态、求值 / 生效顺序、覆盖关系 |
| 数据流 / 管道 | Makefile、jq、RxJS、Shell 管道 | 数据在各级之间如何变形 |
| 异步 / 并发 | JS async、Go goroutine、Rust async | 挂起点、调度、共享状态的竞争风险 |

不确定版本或运行时语义时，标注「需查该语言文档确认」，不要凭印象。

## 2. 通用构造的讲法映射

讲任何语言都绕不开这些构造，但**说法要随语言调整**。

| 构造 | 讲解时必须点明的关键差异 |
|---|---|
| 声明与赋值 | 是"创建新名字"还是"给已有位置写值"；是否有可变 / 不可变之分（`const`、`val`、`let`、Rust 的 `let mut`） |
| 作用域与生命周期 | 块级 / 函数级 / 模块级；变量在哪一刻出生、哪一刻被回收；是否有提升（JS `var`、函数声明） |
| 块边界 | 靠缩进（Python）、大括号（C 系）、`end`（Ruby/Lua）、`then/end`（Shell）。解释"块的边界由什么决定"比逐行念括号更有用 |
| 参数传递 | 值传递 / 引用传递 / 按共享传递。分开说：Python 传的是对象引用的副本，Go 的 slice 传的是描述符，C 传的是地址值 |
| 返回值 | 单返回值 / 多返回值（Go、Lua）/ 元组解包（Python）/ 隐式返回（Ruby、Rust 表达式） |
| 相等性 | `==` 与 `===`（JS）、`==` 与 `equals`（Java）、`is` 与 `==`（Python）、指针相等与结构相等（C/C++/Go/Rust） |
| 类型转换 | 隐式（JS、PHP）与显式；窄化 / 提升；Rust 与 Go 几乎不隐式转换 |
| 错误处理 | 异常（Java、Python）、错误值（Go、Rust）、回调错误优先（Node）、`Result` 类型 |
| 资源释放 | `finally`（Java/Python）、`defer`（Go）、`using`（C#）、RAII / `Drop`（C++/Rust）、`with`（Python） |
| 空值 | `null`、`nil`、`None`、`undefined`、`Option`（Rust/Swift）、零值语义（Go） |
| 迭代 | 下标循环、`for...of` / `for...in`、迭代器协议、`map/filter/reduce`、惰性序列 |
| 并发原语 | 线程、goroutine、Promise / async-await、协程、Actor、channel |
| 元编程 | 宏（C/Rust/Lisp）、装饰器（Python）、注解（Java）、反射、模板（C++） |

## 3. 概念错套清单

初学者最容易被"用另一门语言的概念硬套"误导。以下说法必须避免或明确纠正：

- 把 Python 的 `list` 说成"数组"——它是变长数组，与 C 的定长数组、Java 的 `ArrayList` 语义不同。
- 把 JavaScript 的对象说成"字典 / HashMap"——它是原型链对象，键会被强制转字符串。
- 把 Go 的 `defer` 当成 Java 的 `finally`——前者在函数返回时按栈序执行，且参数在 `defer` 那一刻就已求值。
- 把 Rust 的 `move` 说成"复制"或"传引用"——是所有权转移，原变量随后不可用。
- 把 Java 的"传对象"说成"引用传递"——Java 始终是值传递，传的是引用的值。
- 把 Python 的 `for x in range()` 说成"C 风格循环"——它是迭代协议，不是计数器自增。
- 把 SQL 的 `SELECT` 当成"第一步执行"——逻辑求值顺序是 `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`。
- 把 CSS 的 `!important` 说成"最高优先级"——它仍在层叠规则之内，比它更高的是用户样式表与动画。

拿不准两者差异时，就写"这两者在 X 上的行为不同"，而不是含糊带过。

## 4. 模式 A 的片段样板

逐行表的每一行都要填满三列。示范（Python）：

| 行 | 这行做什么 | 为什么需要它 | 不写会怎样 |
|---|---|---|---|
| 3 | `total = 0` 创建一个叫 `total` 的名字，把数字 0 放进去 | 循环里要往它身上累加，所以必须先把桶清空 | 报 `NameError`；就算不报错也会把上一次残留的值算进去 |
| 4 | `for n in numbers:` 依次把 `numbers` 里的每个元素取出来，命名为 `n`，重复执行缩进的第 5 行 | 逐个处理，这是"批量做同一件事"的标准写法 | 只处理第一个元素，后面的全部被忽略 |
| 5 | `total = total + n` 读出 `total` 当前值，加上 `n`，再把结果写回 `total` | 累加本体 | `total` 永远是 0，函数返回恒为 0 |

块级小结：第 3–5 行构成一个"清零 → 逐个取值 → 累加"的累加器，这是求和类代码的通用骨架。

变量追踪表（输入 `[3, 5, 2]`）：

| 行 | 执行了什么 | 变量当前值 | 输出 |
|---|---|---|---|
| 3 | `total` 初始化为 0 | `total=0` | — |
| 4 | 取第 1 个元素 | `n=3` | — |
| 5 | `0 + 3` 写回 | `total=3` | — |
| 4 | 取第 2 个元素 | `n=5` | — |
| 5 | `3 + 5` 写回 | `total=8` | — |
| 4 | 取第 3 个元素 | `n=2` | — |
| 5 | `8 + 2` 写回 | `total=10` | — |
| 4' | 没有更多元素，循环结束 | — | 10 |

第 4' 行这种"循环结束"也要单独列一行——初学者最常漏掉的就是"循环什么时候停"。

## 5. 模式 B 的片段样板

一句话含义，只写 what，不写 why，不解释基础语法：

| 行 | 代码 | 含义 |
|---|---|---|
| 3 | `total = 0` | 累加器清零 |
| 4 | `for n in numbers:` | 遍历输入序列 |
| 5 | `total = total + n` | 累加 |
| 6 | `return total` | 返回总和 |

关键点提示（≤ 5 条）：
1. 输入的 `numbers` 若非可迭代对象，第 4 行会直接抛 `TypeError`。
2. `total` 若被声明为不可变类型（如某些静态语言），第 5 行需要改成新的绑定而不是写入。
3. 空输入返回 0，不符合"空集合求和应为未定义"的预期时需在调用方兜底。
